A Enterprise API Gateway & Integration Management Platform Founder & Solution Architect · Self-funded startup · India / remote Nov 2024 – Present Beta

An enterprise API gateway and integration management platform — the same category as Kony/Temenos MobileFabric, MuleSoft and IBM API Connect. It gives an organisation a single control layer between client applications and backend systems: services are registered, secured, versioned and observed in one place, and integrations are configured centrally rather than hand-coded into every consuming app. Built from eight years delivering banking channels on top of MobileFabric, where the integration layer decides how fast a bank can ship.

Platform

Java · Spring Boot · Docker · Kubernetes · ReactJS · TypeScript · Oracle

Capabilities

API gateway — routing, authentication and authorisation, rate limiting and throttling, request/response transformation, API versioning and lifecycle management. Integration services — connectors to backend systems, orchestration of multi-service calls, protocol and payload mapping across REST, SOAP and database sources. Identity and session management, a service registry and catalogue, observability (call logging, tracing, error analytics, audit trail), and an admin/developer console for onboarding services and inspecting live traffic.

Architecture

Spring Boot microservices behind a gateway edge · configuration-driven integration definitions persisted in Oracle, so onboarding a new backend service is a configuration change rather than a code release · ReactJS/TypeScript admin console · containerised with Docker, orchestrated on Kubernetes for horizontal scale and rolling deployment.

Responsibilities
  • Defined the gateway boundary, service contract model, and policy/configuration schema.
  • Built the gateway edge and integration service layer in Java and Spring Boot, including transformation and orchestration of backend calls.
  • Designed the configuration-driven onboarding model so integrations are declared, versioned and promoted across environments without redeployment.
  • Built the ReactJS/TypeScript administration console for service registration, policy configuration and traffic inspection.
  • Containerised with Docker and deployed on Kubernetes; owns the full build and deployment path.
  • Uses AI-assisted development (Claude Code, Copilot) across the codebase, working alongside the engineering team to accelerate delivery.
Roadmap

Next phase: exposing registered services to models as typed, governed tools through MCP, so agentic applications — including the Banking Copilot AI Agent — reach enterprise systems through the same policy, audit and observability controls that already govern API traffic.

B Banking Copilot AI Agent Founder & Solution Architect · Self-funded startup · India / remote Nov 2024 – Present In development
Concept

A copilot for banking that runs the end-to-end banking process through chat. The customer or banker states an intent in conversation; the agent interprets it, holds task context across turns, and drives the underlying banking systems to completion — so a journey that today means navigating several screens or channels becomes a single conversation.

Approach

The agent sits between the user and the bank's systems rather than beside them: it decomposes a request into steps, calls the banking services it needs as governed tools, confirms with the user where a decision or authorisation is required, and reports the outcome. Retrieval grounds it in product, policy and account context so answers are sourced rather than recalled.

AI stack

Agentic orchestration & tool-calling · MCP · RAG with embeddings and vector search · Anthropic Claude API · OpenAI API · AWS Bedrock foundation models · Python

Platform

Java · Spring Boot · Python · ReactJS · Docker · Kubernetes · Oracle · AWS — reaches banking services through the Enterprise API Gateway platform above.

Responsibilities
  • Defined the concept and the agent's boundary — which banking actions it may execute, which require human authorisation, and what it must never do unattended.
  • Designed the tool surface over banking services, drawing on nine years of retail and digital banking delivery to model the real process rather than a demo path.
  • Built the orchestration and retrieval layers, model routing across providers, and the conversational front end.
  • Applied banking-grade thinking to guardrails, auditability and failure handling from the start, rather than retrofitting them.
